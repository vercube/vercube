The WebSocket module enables real-time bidirectional communication between clients and your Vercube server using WebSocket connections. Built on top of [crossws](https://crossws.unjs.io/), it provides a decorator-based API that makes WebSocket development intuitive and type-safe.

## Installation

::code-group
  ```bash [pnpm]
  $ pnpm add @vercube/ws
  ```
  ```bash [npm]
  $ npm install @vercube/ws
  ```
  ```bash [bun]
  $ bun install @vercube/ws
  ```
::

## Quick Start

::steps
### Enable the WebSocket Plugin

```ts [src/index.ts]
import { createApp } from '@vercube/core';
import { WebsocketPlugin } from '@vercube/ws';

const app = createApp({
  setup: async (app) => {
    app.addPlugin(WebsocketPlugin);
  }
});
```

### Create a WebSocket Gateway

```ts [src/gateways/ChatGateway.ts]
import { Controller } from '@vercube/core';
import { 
  Namespace, 
  Message, 
  Emit, 
  OnConnectionAttempt 
} from '@vercube/ws';
import type { Peer } from 'crossws';

@Namespace('/chat')
@Controller()
export class ChatGateway {
  
  // Optional: Control connection access
  @OnConnectionAttempt()
  async handleConnection(
    params: Record<string, unknown>, 
    request: Request
  ): Promise<boolean> {
    // Validate authentication token from query params
    const token = params.token as string;
    
    if (!token || !this.isValidToken(token)) {
      return false; // Reject connection
    }
    
    return true; // Accept connection
  }
  
  // Listen for 'message' events from clients
  @Message({ event: 'message' })
  @Emit('message-received')
  async onMessage(
    data: { text: string; user: string }, 
    peer: Peer
  ) {
    console.log(`Message from ${peer.id}:`, data);
    
    // Return value is automatically emitted to the sender
    return {
      status: 'received',
      timestamp: new Date().toISOString()
    };
  }
  
  private isValidToken(token: string): boolean {
    // Your token validation logic
    return true;
  }
}
```

### Connect from the Client

```ts [client.ts]
// Connect to the chat namespace
const ws = new WebSocket('ws://localhost:3000/chat?token=your-auth-token');

// Handle connection
ws.onopen = () => {
  console.log('Connected to chat');
  
  // Send a message
  ws.send(JSON.stringify({
    event: 'message',
    data: {
      text: 'Hello, server!',
      user: 'Alice'
    }
  }));
};

// Receive messages
ws.onmessage = (event) => {
  const message = JSON.parse(event.data);
  console.log('Received:', message);
};

ws.onerror = (error) => {
  console.error('WebSocket error:', error);
};

ws.onclose = () => {
  console.log('Disconnected from chat');
};
```

## Core Concepts

### Namespaces

Namespaces are logical channels that group WebSocket connections. They allow you to organize different types of real-time functionality within your application.

```ts
@Namespace('/chat')    // Chat namespace at ws://yourserver.com/chat
@Namespace('/notifications')  // Notifications namespace
```

Each namespace:
- Has its own connection URL path
- Maintains separate client connections
- Can have different connection handlers
- Isolates message events

#### Parametric Namespaces

A namespace path can hold parameters, with the same syntax as HTTP routes: `:name` for a segment, `*` for an unnamed one and `**:name` for the rest of the path. Every board, document or game gets its own URL, while one gateway serves them all:

```ts
@Namespace('/ws/boards/:boardId')
export class BoardGateway {
  @Message({ event: 'rename' })
  rename(@Data() data: { name: string }, @NamespaceParam('boardId') boardId: string) {
    // ws://server.com/ws/boards/42 → boardId === '42'
  }
}
```

Paths are matched case-insensitively, as static namespaces always were, but parameter names and values keep their case. `@Broadcast()` and `@BroadcastOthers()` reach the peers connected to the same path (`/ws/boards/42`), not every board. `websocketService.getParams(peer)` returns the parameters outside a handler.

### Events

Events are named message types that clients and servers use to communicate. Think of them as typed message channels within a namespace.

```ts
// Server listens for 'message' event from clients
@Message({ event: 'message' })
handleMessage(data: any, peer: Peer) { ... }

// Server emits 'update' event to client(s)
@Emit('update')
sendUpdate() { ... }
```

### Peers

A peer represents a connected WebSocket client. Each peer has:
- **Unique ID**: Automatically assigned identifier
- **Namespace**: The namespace they're connected to
- **IP Address**: Client's IP address
- **Send method**: To send messages directly to that peer

```ts
interface Peer {
  id: string;
  namespace?: string; // the path connected to, such as /ws/boards/42
  context: Record<string, unknown>; // what @OnConnectionAttempt() returned
  send(message: unknown): void; // Uint8Array → binary frame
  close(code?: number, reason?: string): void;
}
```


## Message Flow

Understanding how messages flow through the WebSocket system is crucial:

<img src="/images/wss-1.svg" alt="Message flow"/>

**Connection Flow:**
1. Client initiates WebSocket connection to a namespace
2. Server calls `@OnConnectionAttempt()` handler (if defined)
3. Handler validates connection (query params, headers)
4. Connection accepted/rejected based on handler return value

**Message Flow:**
1. Client sends message with `{ event: '...', data: {...} }`
2. Server matches event to `@Message({ event: '...' })` handler
3. Handler processes message and returns response
4. Response decorators (`@Emit`, `@Broadcast`) send data back

## Message Handlers

### Listening to Events

Use `@Message()` to listen for specific events from clients:

```ts
@Namespace('/chat')
@Controller()
export class ChatGateway {
  
  @Message({ event: 'send-message' })
  handleMessage(data: any, peer: Peer) {
    console.log(`Received from ${peer.id}:`, data);
    // Process message
  }
  
  @Message({ event: 'typing' })
  handleTyping(data: { isTyping: boolean }, peer: Peer) {
    // Handle typing indicator
  }
}
```

### Validation

Add schema validation to ensure message data integrity:

```ts
import { z } from 'zod';

const MessageSchema = z.object({
  text: z.string().min(1).max(500),
  user: z.string(),
  room: z.string().optional()
});

@Message({ 
  event: 'send-message',
  validationSchema: MessageSchema 
})
handleMessage(data: z.infer<typeof MessageSchema>, peer: Peer) {
  // data is typed and validated
  console.log(data.text);
}
```

Invalid messages are automatically rejected with validation errors.

## Sending Messages

### Emit to Sender

Send message back to the client that triggered the handler:

```ts
@Message({ event: 'ping' })
@Emit('pong')
handlePing() {
  return { timestamp: Date.now() };
}

// Client receives: { event: 'pong', data: { timestamp: ... } }
```

### Broadcast to All

Send message to all clients in the namespace (including sender):

```ts
@Message({ event: 'user-joined' })
@Broadcast('user-status')
handleUserJoined(data: { username: string }) {
  return { 
    type: 'joined',
    username: data.username,
    timestamp: Date.now()
  };
}

// All clients receive the message
```

### Broadcast to Others

Send message to all clients except the sender:

```ts
@Message({ event: 'typing' })
@BroadcastOthers('user-typing')
handleTyping(data: { username: string }) {
  return {
    username: data.username,
    isTyping: true
  };
}

// All clients except the sender receive the message
```

## Connection Management

### Accepting Connections

Control who can connect to your namespace:

```ts
@Namespace('/private-chat')
@Controller()
export class PrivateChatGateway {
  
  @Inject(AuthService)
  private authService!: AuthService;
  
  @OnConnectionAttempt()
  async validateConnection(
    params: Record<string, unknown>,
    request: Request
  ): Promise<boolean> {
    const token = params.token as string;
    
    try {
      // Validate JWT token
      const user = await this.authService.verifyToken(token);
      
      // Check permissions
      if (!user.hasPermission('access-private-chat')) {
        return false;
      }
      
      return true;
    } catch (error) {
      return false;
    }
  }
}
```

### Rejecting Connections

Return `false` or throw an error to reject:

```ts
@OnConnectionAttempt()
async validateConnection(params: Record<string, unknown>) {
  if (!params.token) {
    throw new Error('Token required');
  }
  
  const isValid = await this.validateToken(params.token as string);
  
  if (!isValid) {
    return false; // Reject with 403
  }
  
  return true;
}
```

A returned or thrown `Response` is sent as the answer instead, for example to tell the client to log in again:

```ts
@OnConnectionAttempt()
async validateConnection(params: Record<string, unknown>) {
  if (await this.isExpired(params.token as string)) {
    throw new Response('Token expired', { status: 401 });
  }
}
```

Both the production server (`srvx`) and the `@vercube/vite` dev server end the handshake with that response; the socket is never opened.

### Peer Context

An object returned from `@OnConnectionAttempt()` accepts the connection and becomes the context of the peer: it is merged into `peer.context` and reachable from every handler, so the user is authenticated once per connection instead of once per message.

```ts
@Namespace('/ws/boards/:boardId')
export class BoardGateway {
  @OnConnectionAttempt()
  async connect(query: Record<string, string>, request: Request, params: { boardId: string }) {
    const user = await this.auth.fromToken(query.token);
    const role = await this.boards.roleOf(user, params.boardId);

    return role ? { user, role } : false;
  }

  @Message({ event: 'rename' })
  rename(@Data() data: { name: string }, @PeerContext('role') role: string) {
    if (role !== 'editor') throw new ForbiddenError();
  }
}
```

The third argument of the connection handler holds the namespace parameters. `websocketService.getContext(peer)` reads the context outside a handler.

### Allowed Origins

Browsers send cookies with a WebSocket handshake even when another site opens the socket, and the handshake is not covered by CORS. If `@OnConnectionAttempt` authenticates by cookie, a malicious page could connect as the logged in user. The plugin checks the `Origin` header of every upgrade before your connection handler runs and rejects disallowed origins with `403`.

By default only same-origin browser requests are accepted: the host of `Origin` must match the `Host` (or `X-Forwarded-Host`) header of the request. Requests without an `Origin` header, such as server-to-server clients, CLI tools and native apps, are always accepted.

Behind a reverse proxy that rewrites `Host` (nginx does this by default with `proxy_pass`), forward the original host with `proxy_set_header Host $host` or `X-Forwarded-Host`, or list your origin in `allowedOrigins`. Otherwise browser connections are rejected.

When your frontend is served from a different origin, list it with `allowedOrigins`:

```ts [src/index.ts]
app.addPlugin(WebsocketPlugin, {
  allowedOrigins: ['https://app.example.com', 'http://localhost:5173'],
});
```

`allowedOrigins` also accepts a function for custom rules, or `'*'` to turn the check off:

```ts
app.addPlugin(WebsocketPlugin, {
  allowedOrigins: (origin, request) => origin.endsWith('.example.com'),
});
```

With the origin check in place, a cookie-based connection handler only sees requests from trusted pages:

```ts
@Namespace('/chat')
@Controller()
export class ChatGateway {
  @Inject(SessionService)
  private sessionService!: SessionService;

  @OnConnectionAttempt()
  async validateConnection(
    params: Record<string, unknown>,
    request: Request,
  ): Promise<boolean> {
    const session = await this.sessionService.fromCookie(
      request.headers.get('cookie'),
    );
    return !!session;
  }
}
```

## Working with Multiple Namespaces

You can create multiple namespaces for different purposes:

```ts
// Chat namespace
@Namespace('/chat')
@Controller()
export class ChatGateway {
  @Message({ event: 'message' })
  handleMessage(data: any) { ... }
}

// Notifications namespace
@Namespace('/notifications')
@Controller()
export class NotificationsGateway {
  @Message({ event: 'subscribe' })
  handleSubscribe(data: any) { ... }
}

// Admin namespace
@Namespace('/admin')
@Controller()
export class AdminGateway {
  @OnConnectionAttempt()
  async validateAdmin(params: Record<string, unknown>) {
    // Only allow admins
    return this.authService.isAdmin(params.token);
  }
  
  @Message({ event: 'broadcast' })
  @Broadcast('admin-message')
  handleBroadcast(data: any) { ... }
}
```

Clients connect to different URLs:
- `ws://server.com/chat` - Chat namespace
- `ws://server.com/notifications` - Notifications
- `ws://server.com/admin` - Admin only

## Advanced Patterns

### Room-Based Messaging

`WebsocketService` keeps rooms of peers. A room is any name, independent of the namespace, and a peer may be in several. Peers leave their rooms on their own when they disconnect.

```ts
@Namespace('/chat')
export class ChatGateway {
  @Inject($WebsocketService)
  private ws!: WebsocketService;

  @Message({ event: 'join-room' })
  joinRoom(data: { room: string }, peer: Peer) {
    this.ws.join(peer, data.room);
    this.ws.publish(data.room, { event: 'user-joined', data: { userId: peer.id } }, { except: peer });
  }

  @Message({ event: 'room-message' })
  sendToRoom(data: { room: string; text: string }, peer: Peer) {
    this.ws.publish(data.room, { event: 'message', data: { from: peer.id, text: data.text } }, { except: peer });
  }

  @Message({ event: 'leave-room' })
  leaveRoom(data: { room: string }, peer: Peer) {
    this.ws.leave(peer, data.room);
  }
}
```

| Method | Description |
|--------|-------------|
| `join(peer, room)` | Puts the peer in the room |
| `leave(peer, room)` | Takes the peer out of the room |
| `publish(room, data, { except? })` | Sends to every peer in the room, on every instance when an adapter is configured. `except` (a peer or a peer id) skips one, typically the sender |
| `getRoomPeers(room)` | The peers of the room connected to this instance |
| `getPeerRooms(peer)` | The rooms of a peer |

`publish()` sends a `Uint8Array` as a binary frame, a string as text and anything else as JSON text. It never rejects: a failing adapter is logged, and the local peers have the message either way.

### Private Messaging

Send messages between specific peers:

```ts
@Namespace('/chat')
@Controller()
export class ChatGateway {
  private peers = new Map<string, Peer>(); // userId -> Peer
  
  @Message({ event: 'register' })
  registerUser(data: { userId: string }, peer: Peer) {
    this.peers.set(data.userId, peer);
  }
  
  @Message({ event: 'private-message' })
  sendPrivate(data: { to: string; text: string }, sender: Peer) {
    const recipient = this.peers.get(data.to);
    
    if (recipient) {
      recipient.send({
        event: 'private-message',
        data: {
          from: sender.id,
          text: data.text
        }
      });
      
      return { status: 'delivered' };
    }
    
    return { status: 'user-offline' };
  }
}
```

### Heartbeat / Ping-Pong

Dead connections - a laptop that went to sleep, a mobile network that dropped the socket without a `FIN` - are closed by the server itself. On Node it pings every peer and closes the ones that did not answer; Bun and Deno use their native idle timeout. Browsers answer pings without any client code. The interval is `idleTimeout`, in seconds:

```ts
app.addPlugin(WebsocketPlugin, {
  idleTimeout: 30, // default; 0 turns it off
  maxPayload: 1024 * 1024, // close peers sending frames over 1 MiB with code 1009
});
```

`maxPayload` limits the size of a single frame, in bytes. A peer sending a larger one is closed with code `1009` (message too big) before any handler sees the frame. Without it, Node's `ws` caps frames at 100 MiB.

### Presence Tracking

Track online users in a namespace:

```ts
@Namespace('/presence')
@Controller()
export class PresenceGateway {
  private onlineUsers = new Set<string>();
  
  @OnConnectionAttempt()
  async handleConnection(params: Record<string, unknown>) {
    const userId = params.userId as string;
    this.onlineUsers.add(userId);
    
    // Broadcast updated presence
    this.broadcastPresence();
    
    return true;
  }
  
  @Message({ event: 'disconnect' })
  handleDisconnect(data: { userId: string }) {
    this.onlineUsers.delete(data.userId);
    this.broadcastPresence();
  }
  
  private broadcastPresence() {
    // Broadcast to all connected clients
    // Implementation depends on how you track peers
  }
}
```

## Binary Messages

`@Message()` handlers receive `{ event, data }` JSON text. Protocols with their own binary encoding - Yjs, Automerge, protobuf, msgpack - use `@OnBinary()` instead: binary frames of the namespace go to it as a `Uint8Array`, while text frames still go to the `@Message()` handlers.

```ts
@Namespace('/ws/boards/:boardId')
export class BoardGateway {
  @Inject($WebsocketService)
  private ws!: WebsocketService;

  @OnBinary()
  update(@Data() update: Uint8Array, @Peer() peer: Peer, @NamespaceParam('boardId') boardId: string) {
    this.ws.publish(`board:${boardId}`, update, { except: peer });
  }
}
```

Send binary frames with `peer.send(bytes)`, `websocketService.emit(peer, bytes)` or `websocketService.publish(room, bytes)`; set `ws.binaryType = 'arraybuffer'` in the browser to receive them as an `ArrayBuffer`. A namespace without an `@OnBinary()` handler keeps the previous behaviour: a binary frame is decoded as UTF-8 and parsed as a JSON message.

## Lifecycle Hooks

`@OnOpen()`, `@OnClose()` and `@OnError()` run when a peer of the namespace connects, disconnects or fails:

```ts
@Namespace('/ws/boards/:boardId')
export class BoardGateway {
  @OnOpen()
  async open(@Peer() peer: Peer, @NamespaceParam('boardId') boardId: string) {
    await this.documents.load(boardId);
    this.ws.join(peer, `board:${boardId}`);
  }

  @OnClose()
  close(@Peer() peer: Peer, @Data() details: { code?: number; reason?: string }) {
    this.presence.remove(peer.id);
  }

  @OnError()
  error(@Peer() peer: Peer, @Data() error: Error) {
    this.metrics.increment('ws.errors');
  }
}
```

- `@OnOpen()` runs once the peer is counted in the namespace. The messages of the peer wait until it settled, so it may load state or join rooms first.
- `@OnClose()` runs once the peer has left the namespace and every room.
- `@OnError()` runs after the service logged the error.

A hook that throws is logged and does not affect the connection. Without parameter decorators the hooks are called with `(peer)`, `(peer, details)` and `(peer, error)`.

## Handler Parameters

Message handlers are called with `(data, peer)`. Parameter decorators pick what a handler needs instead, in any order:

| Decorator | Injects |
|-----------|---------|
| `@Data()` | The message (`@Message`), the bytes (`@OnBinary`), the close details (`@OnClose`) or the error (`@OnError`) |
| `@Peer()` | The peer |
| `@NamespaceParam(name)` | A parameter of a parametric namespace |
| `@PeerContext(key?)` | The context of the peer, or one key of it |

A parameter without a decorator keeps what the service passed at its position. `@Emit()`, `@Broadcast()` and `@BroadcastOthers()` work on handlers with parameter decorators too.

## Scaling Across Instances

Rooms live in the memory of one process. With several instances behind a load balancer, peers of the same room land on different instances; an adapter relays every `publish()` to the others:

```ts
import { WebsocketPlugin } from '@vercube/ws';
import { RedisWebsocketAdapter } from '@vercube/ws/adapters/RedisAdapter';

app.addPlugin(WebsocketPlugin, {
  adapter: new RedisWebsocketAdapter({ url: process.env.REDIS_URL }),
});
```

`RedisWebsocketAdapter` needs the optional `ioredis` dependency. It uses one Redis channel per room (`<prefix>:room:<room>`), so an instance only receives the rooms it has peers in, and carries binary payloads as bytes. Pass `client` to reuse a connection (the adapter subscribes on a duplicate and never closes the client it was given) and `prefix` to separate applications sharing a Redis.

Each instance has an id (`websocketService.instanceId`) sent with its publishes, and drops its own messages when they come back, so a peer never receives a message twice.

An application keeping state per room on the server - a shared document, a game - listens to what the other instances publish:

```ts
@OnOpen()
open(@Peer() peer: Peer, @NamespaceParam('boardId') boardId: string) {
  const room = `board:${boardId}`;

  this.ws.join(peer, room);
  this.stops.set(peer.id, this.ws.onRemoteMessage(room, (data) => this.documents.apply(boardId, data)));
}
```

`onRemoteMessage(room, listener)` returns a function removing the listener; the room stays subscribed while a listener or a local peer needs it. `MemoryWebsocketAdapter` with a shared `MemoryWebsocketBus` does the same within one process, for tests. Any other backplane implements `WebsocketTypes.Adapter`: `init(instanceId, onMessage)`, `subscribe(room)`, `unsubscribe(room)`, `publish(message)` and `close()`.

`app.close()` closes every peer with code `1001` and closes the adapter.

## Testing

`@vercube/testing/ws` connects an in-memory client to a gateway, through the same upgrade, open, message and close hooks a real server calls:

```ts
import { createTestApp } from '@vercube/testing';
import { connectWebsocket, testWebsocket } from '@vercube/testing/ws';

const app = await createTestApp({ providers: [BoardGateway], extensions: [testWebsocket()] });

await expect(connectWebsocket(app, '/ws/boards/1')).rejects.toThrow(/rejected with 403/);

const ws = await connectWebsocket(app, '/ws/boards/1', { query: { token: 'secret' } });
await ws.send(new Uint8Array([1, 2, 3]));
await ws.emit('rename', { name: 'Roadmap' });
expect(await ws.nextEvent('renamed')).toEqual({ name: 'Roadmap' });
```

## Error Handling

### Handler Errors

Errors in message handlers are caught, logged and reported to the peer with an `error` frame (see [Validation Errors](#validation-errors)). To answer with your own payload instead, catch the error and return it from a handler decorated with `@Emit()`, which sends the return value to the peer:

```ts
@Message({ event: 'risky-operation' })
@Emit('risky-operation-result')
async handleRiskyOp(data: any, peer: Peer) {
  try {
    const result = await this.performOperation(data);
    return { success: true, result };
  } catch (error) {
    console.error('Operation failed:', error);
    return { 
      success: false, 
      error: error.message 
    };
  }
}
```

### Validation Errors

Schema validation errors are automatically handled:

```ts
const StrictSchema = z.object({
  name: z.string().min(3),
  age: z.number().positive()
});

@Message({ 
  event: 'submit',
  validationSchema: StrictSchema 
})
handleSubmit(data: z.infer<typeof StrictSchema>) {
  // If validation fails, this handler never runs
  // `data` is the parsed value: coercions, defaults and transforms apply
}
```

When validation fails the peer receives an `error` frame with the issues:

```json
{
  "event": "error",
  "data": {
    "event": "submit",
    "status": 400,
    "message": "Websocket message validation error",
    "issues": [...]
  }
}
```

An error thrown by a handler is reported the same way, as `{ "status": 500, "message": "Failed to process message" }` unless it is an `HttpError`, and logged on the server. A `validationSchema` needs a registered `ValidationProvider`, otherwise registering the handler fails at boot.

## Troubleshooting

**"Namespace not registered"**
```bash
# Error: Namespace "/chat" is not registered. Connection rejected.
```
**Solution:** Make sure your gateway class has the `@Namespace()` decorator

**"No message handler for event"**
```bash
# Warning: No message handler for event "foo" in namespace "/chat"
```
**Solution:** Add a `@Message({ event: 'foo' })` handler or check event name spelling

**"WebsocketService is not registered"**
```bash
# Warning: MessageDecorator::WebsocketService is not registered
```
**Solution:** Add `WebsocketPlugin` to your app setup

**Validation errors**
```bash
# Message validation error: [{ path: 'text', message: 'Required' }]
```
**Solution:** Check your message data matches the validation schema
