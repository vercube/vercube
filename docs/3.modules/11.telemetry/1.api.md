## Telemetry

The dependency-injection token, bound only when telemetry is enabled. Inject it with `@InjectOptional` from code that must also run without it.

```ts
import { Inject } from '@vercube/di';
import { Telemetry } from '@vercube/telemetry';

class ReportService {
  @Inject(Telemetry)
  private gTelemetry!: Telemetry;
}
```

### span

```ts
span<T>(name: string, fn: (span: Span) => T, options?: SpanOptions): T
```

Runs `fn` inside a new span that ends when the work settles. The return value is passed through unchanged, so wrapping synchronous code does not make it asynchronous.

```ts
const total = this.gTelemetry.span('report.total', (span) => {
  span.setAttribute('report.rows', rows.length);
  return rows.reduce((sum, row) => sum + row.amount, 0);
});
```

### activeSpan, traceId, spanId

```ts
activeSpan(): Span | undefined
get traceId(): string | undefined
get spanId(): string | undefined
```

The span active on the current async execution path, and its ids in lowercase hex. Useful for putting a trace id into an error response so a user can quote it in a bug report.

### inject, extract

```ts
inject(carrier: Headers | Record<string, string>): void
extract(headers: Headers | Record<string, string>): Context
```

Write W3C trace context headers for the active span into a carrier, or read them back into a context usable as a span parent. `extract` is what lets a background worker continue the trace of the request that queued its job.

### onFlush, flush

```ts
onFlush(flush: () => Promise<void>): void
flush(): Promise<void>
```

`flush()` pushes out everything buffered by batching exporters and drains. Call it before a process that may be frozen or killed goes away. `onFlush` registers additional work to run when it does.

### tracer, meter

The underlying OpenTelemetry `Tracer` and `Meter`, for anything the wrapper does not cover, such as creating your own counters and histograms.

```ts
const refunds = this.gTelemetry.meter.createCounter('billing.refunds');
refunds.add(1, { 'billing.reason': reason });
```

## @vercube/telemetry/sdk

Everything that needs the OpenTelemetry SDK lives behind this subpath, so the main entry stays API-only.

### startNodeTelemetry

```ts
startNodeTelemetry(options?: NodeTelemetryOptions): Promise<NodeTelemetry>
```

Wires a Node tracer provider and registers it globally. Accepts `serviceName`, `serviceVersion`, `environment`, `resourceAttributes`, `sampler`, `endpoint`, `headers`, `exporter` and `spanProcessors`. Returns a handle with `shutdown()`.

The context manager and the propagator are deliberately not replaced: `TelemetryPlugin` already installed ones backed by Vercube's request context, and letting the SDK swap them in would open a second `AsyncLocalStorage` frame per request.

### addSpanProcessor

```ts
addSpanProcessor(processor: SpanProcessor): () => void
```

Adds a span processor whether or not a provider exists yet. This is how a package can observe spans without owning the SDK setup, and it works the same whether the application called `startNodeTelemetry` first, later, or never.

### addMetricReader, ensureMeterProvider

```ts
addMetricReader(reader: IMetricReader): () => void
ensureMeterProvider(options?: NodeTelemetryOptions): MeterProvider
```

Metric readers have to be registered before the provider is built, and instruments have to be created after it exists. The OpenTelemetry metrics API has no proxy meter, so an instrument created before a provider is registered stays a no-op for the life of the process.

## @vercube/telemetry/testing

### createTestTelemetry

```ts
createTestTelemetry(): TestTelemetry
```

Registers in-memory tracer and meter providers plus a context manager, and hands back everything a test needs to assert on what was recorded.

```ts
import { createTestTelemetry } from '@vercube/telemetry/testing';

const telemetry = createTestTelemetry();

afterEach(() => telemetry.reset());
afterAll(() => telemetry.shutdown());

it('traces the request', async () => {
  await app.fetch(new Request('http://localhost/users/1'));

  expect(telemetry.span('GET /users/:id')).toBeDefined();
});
```

`spans()` returns finished spans, `span(name)` finds one, `collect()` collects the registered instruments, `settle()` waits for spans whose end was deferred (body capture defers it), and `reset()` clears everything between tests.
