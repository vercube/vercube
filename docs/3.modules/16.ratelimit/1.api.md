## @RateLimit()

```ts
@RateLimit(options?: Partial<RateLimitTypes.Options> | false)
```

Limits a route, or every route of a controller. `false` lifts every limit, the app-wide one included. Options left out come from the `rateLimit` config section. A limit that gets no `limit` or no `window` from either answers 500 with a `RateLimitError` on every request: the config is only known once the app runs, so this cannot be checked when the class is defined.

| Option | Default | Description |
| --- | --- | --- |
| `limit` | config | Requests allowed per window. A positive integer. |
| `window` | config | Length of the window: milliseconds, or a string such as `'30s'`, `'1m'`, `'1h30m'`. Units are `ms`, `s`, `m`, `h` and `d`. |
| `algorithm` | `'fixed'` | `'fixed'` or `'sliding'`, see [Algorithms](/docs/modules/ratelimit/overview#algorithms). |
| `key` | client address | `({ request, ip, context }) => string \| null \| undefined`, may be async. `null`, `undefined` or `''` leaves the request unlimited. `context` is null without a request context. |
| `storage` | `'default'` | Storage mount the counters live in. A missing `default` is replaced by memory, a missing named mount fails like a storage that is down. |
| `onStorageError` | `'allow'` | `'allow'` lets requests through when the storage fails, `'deny'` answers 503. |
| `priority` | `-900` | Middleware priority. Below `-999` runs before `@Auth()`. Set it on each decorator: in the config it only applies to the app-wide limit. |
| `headers` | `true` | Sends `RateLimit-Limit`, `RateLimit-Remaining` and `RateLimit-Reset`. |
| `name` | `Controller.method` | Counter name. Limits with the same name share a counter. A controller-wide limit defaults to the class name. The class is the route's own, a subclass's when it inherits the route. In the config it only names the app-wide limit. |

Invalid options throw a `RateLimitError` when the class is defined, so a typo fails at startup.

Two `@RateLimit()` on the same method keep the one written closest to it. A subclass's `@RateLimit()` replaces the one it inherited and leaves the parent class untouched.

## @SkipRateLimit()

Same as `@RateLimit(false)`.

## RateLimitPlugin

Applies the `rateLimit` section. Options given to the plugin are merged over the section.

```ts
export default defineConfig({
  rateLimit: { limit: 300, window: '1m', storage: 'redis' },
  plugins: [RateLimitPlugin],
});

// or, overriding the section
app.addPlugin(RateLimitPlugin, { trustProxy: 2 });
```

`@RateLimit()` also works without the plugin: the manager and the `StorageManager` are bound on first use. The `rateLimit` config section is then ignored, `trustProxy` included, and a warning says so once.

## The rateLimit config section

`RateLimitTypes.Config`, added to `ConfigTypes.Config` by `@vercube/ratelimit`. Every field of `@RateLimit()` is accepted as a default, plus:

| Option | Default | Description |
| --- | --- | --- |
| `trustProxy` | `false` | Proxies to trust when reading the client address. A number counts hops from the right of `x-forwarded-for`, `true` takes the leftmost entry. See `getRequestIP()` below. |

With both `limit` and `window` set, the section is also the app-wide limit, named `global` unless `name` says otherwise.

## RateLimitManager

Bound by the plugin, resolved from the container.

### reset()

```ts
// every counter
await rateLimits.reset();
// one counter, every client
await rateLimits.reset('AuthController.login');
// one client of one counter, also in the 'redis' mount
await rateLimits.reset('AuthController.login', ip, { storage: 'redis' });
```

Deletes counter keys in the mounts this process counted in, the default mount (`rateLimit.storage`, or `default`), and the mounts passed in `storage`. Pass `storage` on an instance that has not counted anything yet, such as an admin process resetting a shared Redis. It never clears a mount, which is usually shared with application data. It lists the mounts' keys, so keep it for tests and admin tools.

### consume()

```ts
const exports = rateLimits.resolve({
  scope: 'global',
  name: 'exports',
  limit: 5,
  windowMs: 3_600_000,
});

const result = await rateLimits.consume(exports, userId);
// { allowed, limit, remaining, resetAt, retryAt? }
```

Counts one request without going through a route, for a job or a WebSocket message. Throws when the storage fails.

### configure() and defaults

`configure(defaults)` merges defaults over the current ones, the way the plugin applies the config section. `defaults` returns them.

## getRequestIP()

From `@vercube/core`:

```ts
getRequestIP(request: Request, options?: { trustProxy?: boolean | number }): string | null
```

Returns the client address, or `null` when nothing tells it. Without `trustProxy` it is the socket address and every header is ignored. With a number, it is the `x-forwarded-for` entry that many hops from the right.

## Testing

`withRateLimit()` from `@vercube/ratelimit/testing`:

```ts
import { withRateLimit } from '@vercube/ratelimit/testing';

const limits = withRateLimit({ limit: 100, window: '1m' });
const app = await createTestApp({
  controllers: [AuthController],
  extensions: [limits],
});

afterEach(() => limits.reset());
```

| Option | Default | Description |
| --- | --- | --- |
| `client` | `'test-client'` | Who a test request counts against when it has no address. |
| any `rateLimit` field | | Settings for the test. |

It registers `RateLimitPlugin`, or adds its settings to the one the test registered (an app-wide limit then belongs on that plugin). It mounts a memory storage under the limits' `storage` unless the test mounted one; a route with a `storage` of its own needs that mount from the test. A `key` from the options or the app config is kept. `limits.manager` is the app's `RateLimitManager`, until the app closes.

## Errors

| Error | From | When |
| --- | --- | --- |
| `TooManyRequestsError` | `@vercube/core` | A client is over the limit. Status 429. |
| `ServiceUnavailableError` | `@vercube/core` | The storage failed and `onStorageError` is `'deny'`. Status 503. |
| `RateLimitError` | `@vercube/ratelimit` | An option is invalid: thrown when the class is defined or the plugin is applied. A limit left without `limit` or `window` throws it on each request instead, answered with 500. |
