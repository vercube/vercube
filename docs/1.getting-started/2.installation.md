## Quick start
Before you begin, make sure you have one of the following runtime environments installed:
- [Node.js](https://nodejs.org/en) >= 22.0.0
- [Bun](https://bun.sh) >= 1.2.0
- [Deno](https://deno.land) >= 2.0.0

::alert{type="secondary" icon="lucide:info"}
  We recommend using the latest stable versions of these runtimes for the best experience.
::

::steps
  ### Create a new project
  The project generator asks what you are building and which modules to include, and wires them in:
  ::code-group
    ```bash [pnpm]
    $ pnpm create vercube@latest
    ```
    ```bash [npm]
    $ npx create-vercube@latest
    ```
    ```bash [bun]
    $ bun create vercube
    ```
  ::

  ::cli-wizard
  ---
  steps:
    - question: Where would you like to create your project?
      answer: ./my-app
    - question: What are you building?
      options: ["API only", "Fullstack: Vercube + Vue"]
      selected: ["API only"]
    - question: Which modules do you want?
      multiple: true
      options: ["Schema / OpenAPI", "Auth", "Queue", "Scheduler", "Storage", "Cache", "Rate limit", "WebSockets", "Telemetry", "Devtools", "Testing"]
      selected: ["Schema / OpenAPI", "Devtools", "Testing"]
    - question: Queue driver?
      hint: only with Queue
      options: ["BullMQ", "RabbitMQ", "Kafka", "Memory"]
      selected: ["BullMQ"]
    - question: Deploy target?
      options: ["Node, Bun or Deno server", "AWS Lambda", "Azure Functions"]
      selected: ["Node, Bun or Deno server"]
    - question: Package manager?
      answer: pnpm
  ---
  ::

  Every question has a flag, so the same project can be created in CI or by an agent:

  ```bash
  $ pnpm create vercube my-app \
      --template api \
      --modules schema,queue,testing \
      --queue bullmq \
      --deploy node \
      --yes
  ```

  [Project generator](/docs/getting-started/project-generator) lists every template, module and flag.

  ### Enter the project
  ```bash
  $ cd my-app
  ```

  A module that needs a broker or a database (BullMQ, RabbitMQ, Kafka, the Redis or Postgres scheduler store) adds it to `docker-compose.yml`, and its connection to `.env`. When the project has one, start it with Docker:

  ```bash
  $ docker compose up -d
  ```

  ### Start the development server
  ::code-group
    ```bash [pnpm]
    $ pnpm dev
    ```
    ```bash [npm]
    $ npm run dev
    ```
    ```bash [bun]
    $ bun run dev
    ```
  ::

  `curl localhost:3000/api/foo` answers `{"message":"Hello, world!"}`. Each module adds a small working example next to it, such as `POST /api/jobs/welcome` for the queue. A fullstack project serves the Vue app on `http://localhost:5173`.

  ::tip
  The development server rebuilds and restarts on every change.
  ::
::

## Adding a module later

The recipes the generator applies also work on an existing project, through the project's own CLI:

::code-group
  ```bash [pnpm]
  $ pnpm vercube add queue --queue bullmq
  ```
  ```bash [npm]
  $ npx vercube add queue --queue bullmq
  ```
  ```bash [bun]
  $ bunx vercube add queue --queue bullmq
  ```
::

Adding a module twice changes nothing, so it is safe to run again. It does not reconfigure one either: adding the queue again with another driver adds that driver's packages and service, but the plugin keeps the driver it was set up with.
